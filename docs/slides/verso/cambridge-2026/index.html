Top-Level Result

Trusted base outside the statement

  • The machine model. stepSp1 from riscv-zkvm (unmodified, pinned) is taken to be SP1's actual semantics, including how it handles syscalls (hint reads, halt).

  • The loaded image. start I is built from image data generated from the ELF. The gen-image tool cross-checks that data against riscv-zkvm's own loader, and every fact about it is kernel-checked. Still, what we prove about is "the image as generated", so the generator and that cross-check are part of the trust story.

  • Lean itself. That's the kernel and the three standard axioms, plus bv_decide's Lean.ofReduceBool if it's on this theorem's path. That last one trusts the compiler much as native_decide does; your policy allows it, and #print axioms will tell us whether it appears.

  • Not in the base anymore: the Pallas native_decide is gone. The spec audit now proves all 13 entries on standard axioms, Pallas group included.

ISA Diversity

Note that Zisk and SP1 differ in:

  • Calling convention for special operations

  • Memory layout and access rules

  • Input and output, etc.

  • Calling convention for special operations: ZisK and SP1 use different mechanisms to request accelerated cryptography and other host services.

  • Memory layout and access rules: they place the program, stack, heap, and input differently and enforce different valid-address rules.

  • Input and output: SP1 has its own conventions for reading private input and committing public output.

  • Available special operations: each zkVM exposes a somewhat different collection of built-in operations.
